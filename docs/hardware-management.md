# 虚拟机硬件与模板授权

现有实例硬件变更仅管理员可提交；前端隐藏控件不替代后端权限校验。所有变更使用异步任务、节点状态二次校验、资源互斥及审计。首期为关机配置，不自动关闭运行中的实例。

- CPU、内存调整：检查节点剩余容量和资源所有者配额，CPU 拓扑明确调整为 1 插槽 × N 核 × 1 线程。NUMA、直通、CPU 绑定等特殊实例拒绝自动改写。
- 数据盘新增与重新挂载：受控目录中的 QCOW2、VirtIO/SATA 总线，不接受前端文件路径。
- 数据盘删除：卸载并保留文件，保留的容量继续计入配额；支持重新挂载。禁止卸载系统盘。不执行数据文件永久删除。
- 磁盘扩容：仅增大 QCOW2 容量，复核节点实际容量，客体分区和文件系统由管理员在客体内扩展。禁止缩小。
- 网卡新增、移除：仅白名单业务网络，固定生成唯一 MAC；删除带静态 IP 租约的网卡前须先处理地址配置，避免泄漏租约与地址冲突。
- 请求超时或结果未知时保留资源预留；在任务中心重试原任务，先按实际设备核对，不重复分配磁盘文件、设备名或 MAC。
- 任务从未执行时可取消并释放预留；已尝试执行的硬件任务不可用取消来丢弃未知结果。存在快照的实例需先处理快照一致性，节点拒绝直接修改。

入口：虚拟机详情的“硬件 / 磁盘 / 网络”；管理员可操作，普通用户仅查看。硬件修改 API 为 `GET/POST /api/v1/admin/vms/{id}/hardware/`；POST 只接受对应操作的字段，不接受磁盘绝对路径、任意 XML 或宿主机命令。

数据盘支持 `disk-add`、`disk-detach`、`disk-attach`、`disk-resize`，网卡支持 `nic-add`、`nic-remove`，计算资源支持 `compute`。修改显卡、启动显示尺寸和剪贴板继续使用已有 display API。

模板发布界面支持硬件配置、数据盘清单、网卡型号、数据盘总线、主网络与附加网络。硬件清单固定继承，磁盘文件和 MAC 在部署时唯一生成。该设置不会修改从该模板已创建的实例。

模板可对全体用户公开，或仅分配给指定用户。管理员维护模板和发布版本；用户仅能读取并使用可见的已发布版本，不能通过猜测 ID、预检查接口或直接创建接口绕过分配。管理员删除分配后，不影响已经创建的实例，但禁止再次使用该模板部署。用户不可覆盖模板中的高级硬件、数据盘和附加网卡配置。模板发布版本保持不可变，改动生成新版本。
