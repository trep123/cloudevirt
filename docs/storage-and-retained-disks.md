# 存储目录和保留磁盘

## 目录存储池

管理员在存储池创建表单中填写 Linux 绝对目录；留空时使用节点磁盘根目录下的同名子目录。
节点返回 `storage_roots` 和 `default_directory`，前端展示实际允许范围。
缺失子目录自动创建；现有目录不会被清空或修改权限。拒绝目录穿越、符号链接逃逸、
同名异路径、重复目标目录。创建仍使用幂等键和异步任务，成功后由 libvirt 管理和自启。
同一文件系统下多个目录池共享容量，创建池不会迁移既有虚拟机磁盘。

默认范围为 `CLOUDVIRT_DISK_DIR`。新增挂载目录时，节点管理员可在
`/etc/cloudvirt/agent.env` 配置逗号分隔的 `CLOUDVIRT_STORAGE_ROOTS`，例如
`CLOUDVIRT_STORAGE_ROOTS=/mnt/cloudvirt,/srv/cloudvirt`。
需要提前建立这些根目录，并为 `cloudvirt-agent` 和宿主机实际 QEMU 用户配置访问权限及
默认 ACL；在 Agent 的 systemd drop-in 增加对应 `ReadWritePaths`，daemon-reload 后重启 Agent。
此设置扩大的是明确存储目录的访问范围，不需要把 Agent 改为 root。

## 删除实例时的磁盘选项

默认保留磁盘。拥有 `instances.delete_disk_instance` 权限的用户可勾选同时删除关联磁盘。
确认弹窗列出磁盘名称、角色、容量及卸载状态，并明确数据和内部快照不可恢复。
服务端按权限校验参数，节点仍要求 `CLOUDVIRT_ALLOW_DESTRUCTIVE=true`。
被保留的磁盘继续计入原用户配额，已删除记录不会因删除实例而重新变成 READY。
只有节点确认清理完成后，后端才标记磁盘 DELETED。

## 单独清理磁盘

“数据卷 → 仅保留 / 已卸载磁盘”包含已删除实例留下的文件和硬件模块已卸载的数据盘。
普通用户只可访问自己授权节点上的原有磁盘，管理员按既有资源规则管理。
只有孤立且所属实例已删除，或明确 DETACHED 的磁盘才允许请求删除。
删除使用独立异步任务、幂等键、资源互斥、执行时权限复核和审计。

节点在删除前核对所有运行/持久域定义、快照 XML 和 QCOW2 backing/data-file 依赖。
无法读取定义或依赖时停止删除；域/快照引用与硬链接别名均不能绕过检查。
受管磁盘删除与 Agent 的域/硬件/快照变更互斥；不应同时通过节点外部工具手工修改依赖。
文件已缺失时可以幂等完成登记清理。发生超时或部分失败时，先核对任务，再手动重试。
成功后更新磁盘状态、配额和实例磁盘清理标记，不删除历史审计记录。

此入口不自动清理此前刻意保留的 NVRAM/TPM 状态、安装镜像或其他非磁盘文件。
