# 固定部署模板与物理桥接网络

## 模板发布与使用

管理员在“规格模板 → 发布部署版本”指定镜像、目标节点、CPU、内存、系统盘、
数据盘、CPU 拓扑/模式、固件、安全启动、TPM、显卡及首选尺寸、剪贴板通道、
磁盘总线、网卡型号、性能限制、启动策略和可选 cloud-init 用户/SSH 公钥。
能力选项由所选节点返回；实际创建前仍检查兼容性、镜像摘要和容量。
普通用户只能使用公开或明确分配的模板，不能编辑/发布版本。

选择已发布部署模板后，创建页面只填写实例名称和各网卡接入网络。
客户端提交 `name`、`template_version`、`network_name`、`additional_networks`，
其余配置由服务端解析。核心配置不能通过直接 API 覆盖，附加网卡数量固定。
各网卡使用不同的可用网络；接入网络可以重新选择，但不改变型号和数量。
空的主网络表示不接入。每次创建生成独立磁盘、UUID 和 MAC。

节点优先使用版本指定节点，其次使用镜像所在节点。没有绑定节点的旧版本，
会尝试选择具有操作授权的可调度节点；配置不足或容量不足会明确失败。
修改已发布配置需发布新版本，旧实例保持原配置。SSH 公钥会应用到每台模板实例，
不保存或分发宿主机密码。ISO 安装仍需要用户完成客体系统安装。

## 创建网桥

管理员进入“网络管理 → 创建桥接网络”，选择在线节点、Linux Bridge 或 OVS、
新网桥设备名和未占用的物理网卡，确认具体接口与网桥后提交异步任务。
OVS 只在节点已安装并启动 Open vSwitch 时提供；安装程序仍支持 `--enable-ovs`。
创建成功要由节点核验网桥及物理端口，未就绪记录不能用于虚拟机创建或添加网卡。
网桥绑定单个节点，其他节点不得使用该网络。

排除以下接口：

- 带 IPv4 地址或非链路本地 IPv6 地址的接口。
- 承载默认路由、静态路由或多路径路由的接口。
- 已加入网桥、OVS 或 bond 的接口，以及已被托管配置预留的接口。
- 不是实际物理设备的接口。
- `CLOUDVIRT_PROTECTED_INTERFACES` 指定的接口，即使暂时没有地址或处于离线状态。

如果有未启用的备用管理口，在 `/etc/cloudvirt/network.env` 配置
`CLOUDVIRT_PROTECTED_INTERFACES=ens33,ens34`，然后重启 `cloudvirt-network`。
自动检测以节点当前地址、路由及归属为准，不能推断尚未启用且未标记的管理用途。

本功能创建二层桥接，不迁移管理地址、不改默认路由、不执行全局 netplan apply，
不自动提供 DHCP、NAT 或跨节点共享。物理网络负责 DHCP/网关；登记地址规划不代表
宿主机已启动对应服务。

## 权限、持久化与故障

公开 Agent 继续以非 root 运行，只通过受限 Unix socket 调用 `cloudvirt-network`。
网络服务只拥有 CAP_NET_ADMIN，持久配置存放在 `/var/lib/cloudvirt/network/*.json`，
运行 socket 位于 `/run/cloudvirt-network/network.sock`。socket 只允许 root 与
cloudvirt-agent 组访问。系统启动时网络服务从持久配置恢复网桥。

POST `/api/v1/networks/bridges` 必须携带幂等键，相同请求复用任务，变更请求不能复用
相同键。数据库登记、任务和审计在同一事务创建。任务执行前再次检查管理员权限。
部分创建失败或请求响应丢失时保留配置与接口预留；“核对并重试”使用相同配置检查
现有结果，不接管外部网桥，也不自动删除可能已经投入使用的设备。

已有网桥仍可通过原来的“登记网络”入口登记。托管网桥禁止仅删除数据库记录或通过
登记接口变更桥接属性。本轮没有提供自动解绑/删除物理桥接功能；需要清理时，应先
迁出关联实例，由节点管理员安全解除端口、删除网桥及相应托管 JSON，再核对登记记录。
页面状态是上次创建核验结果，不等于连续采集的实时链路监控。

网络服务日志：`journalctl -u cloudvirt-network -u cloudvirt-agent -u cloudvirt-worker`。
