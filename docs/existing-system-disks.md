# 已有系统盘创建虚拟机

管理员在手动创建向导的基本信息页选择“已有系统磁盘”，不再选择镜像；源盘所在节点固定，新盘容量不得小于源盘。其余 CPU、内存、硬件、网络和启动策略仍可配置。部署模板与已有系统盘为互斥来源；已有系统盘不注入 cloud-init 或静态地址初始化。需要配置系统内部网络时可通过控制台修改。

该功能将保留的系统磁盘独立克隆为新实例磁盘，原盘不变，不会把同一盘同时交给多个实例写入。保留原有操作系统、软件与内部账号配置；克隆后如有需要应自行更新主机名与网络配置等系统身份信息。

候选仅限数据库登记的独立 QCOW2 系统盘、已删除实例保留盘或已卸载盘、未删除、未被实例占用；不接受浏览器提交节点文件路径。GET /api/v1/admin/vms/system-disk-sources/ 提供候选，创建/预检提交 existing_system_disk（磁盘 ID），普通用户无权列出或使用，直接构造请求同样拒绝。

正式提交在节点行锁内重新校验，任务快照记录源磁盘 ID 与路径；使用幂等键避免重复创建。源盘在活跃克隆任务期间无法删除，节点复制期间亦持有磁盘引用读锁，防止节点受管删除操作并发删除源文件。节点检查运行域、持久定义、快照及 backing/data-file 引用，拒绝被引用或依赖外部文件的源盘；独立复制并原子发布目标，禁止覆盖已有目标。权限在任务执行前再次核对。

管理员高级硬件表单不再因节点能力尚未返回而整体误标记为“管理员配置，仅查看”。具体 TPM、UEFI 等能力仍按节点真实支持情况开放；普通用户与固定模板的硬件限制保持后端强制执行。
