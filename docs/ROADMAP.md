# CloudVirt 开发路线图

- 版本：1.0（草案）　日期：2026-10-26
- 上游：《手册》第 20 章分阶段实施计划；任务细节见 docs/IMPLEMENTATION_TASKBOOK.md
- 排序原则：按**依赖顺序**推进，不承诺工期；每阶段以“门禁（Gate）”判定是否可进入下一阶段。

## 1. 总体目标与边界

- MVP 目标：单节点可用的云虚拟化管理平台（节点注册与心跳、镜像登记、实例创建与生命周期、任务与审计、只读监控）。
- MVP **非目标**（《手册》1.2，不得用界面按钮替代真实功能）：在线迁移、自动 HA、分布式共享存储、多租户强隔离网络、生产级备份平台、完整 cloud-init 自动化、公网直连 Agent、未经验证的嵌套虚拟化。
- 当前环境约束：开发机无 `/dev/kvm`、无 Go、无 PostgreSQL；阶段 3 及以后的**真实环境验收**须在独立 KVM 宿主机执行，否则标记 BLOCKED / NOT VERIFIED。

## 4. 关键路径与可并行项

- **关键路径**：A（工程基线） → L（API 规范） → B（认证） → D（Agent） → C（心跳） → J（任务） → G（状态机） → E/F（镜像与磁盘） → H/I（生命周期） → N/O（可靠性与安全） → P（生产化）。
- **可并行**：
  - 前端 K 与后端 L/B 并行（以契约为准，前端可用 mock 先行，联调前切换真实 API）；
  - Agent D 与后端 C/J 并行（先固定 Agent 契约，后端按契约实现客户端）；
  - 镜像 E 与磁盘 F 可在 Agent 存储模块就绪后并行推进；
  - 监控 N 的采集部分可在 C 完成后提前启动，对账与修复部分依赖 J。
- **阻塞优先**：Go 工具链安装、PostgreSQL 实例、KVM 宿主机 —— 三项外部依赖应在阶段 1 内落实，否则 M3/M5 无法验收。

## 6. 阶段门禁（Gate）检查项

- **G0 → 阶段 1**：审计结论入库；目录结构确认；外部依赖（Go/PostgreSQL/KVM 宿主机）责任人明确。
- **G1 → 阶段 2**：三组件启停成功；健康检查通过；密钥扫描无命中；API 前缀与错误结构已统一。
- **G2 → 阶段 3**：心跳离线/恢复判定正确；资源展示含采样时间与过期标记；任务框架可用（worker 不重复领取）。
- **G3 → 阶段 4**：真实 KVM 上创建/启动/关机/删除全链路通过；`virsh dominfo` 与数据库一致；磁盘与镜像引用关系正确；孤儿扫描能发现注入差异。
- **G4 → 阶段 5**：权限矩阵用例全绿；幂等键与任务恢复用例通过；威胁测试无阻断级缺陷；Agent 网络访问受限已验证。
- **G5 → 阶段 6**：多节点资源汇总正确；故障节点停止调度；跨节点镜像可用性校验生效。
- **G6 → 生产候选**：备份恢复演练完成；升级回滚 runbook 可执行；生产配置（DEBUG 关闭、TLS/mTLS、最小权限）验证通过。
