# 任务效率与布局优化

## 执行与调度

- Worker 由单任务串行调整为有界线程池，默认并发 2，`--concurrency 1..8` 或 `CLOUDVIRT_WORKER_CONCURRENCY` 可配置。小规格节点建议保持 1–2，不能将并发数理解为宿主机容量。
- 领取仍采用 PostgreSQL skip_locked 与同资源活动任务唯一约束。资源预留、配额及节点锁不取消；不同资源可并行，不允许同一资源操作重叠。
- `--once` 保持同步执行一个任务，`--max-tasks` 控制本轮领取总数，不提前领取超出线程容量的任务。
- 每个执行线程独立管理数据库连接，任务结束后关闭连接。SIGTERM/SIGINT 后停止领取并等待当前任务结束，systemd 等待上限 660 秒；超过上限或断电仍需原有状态对账，不能盲目重放危险操作。
- 空闲轮询默认从 2 秒改为 0.5 秒，降低提交后等待领取的时间；这增加少量空闲数据库查询，可通过 --sleep 调整。
- 节点容量检查改为数据库 SUM 聚合，不再把全部实例/磁盘载入 Python。保留原有保守磁盘预留算法，已删除磁盘不再计算；没有放松超分规则。
- 任务列表不加载展示无关的 payload/result 大字段，增加服务端状态筛选。未引入能力缓存或跳过镜像校验，也不声称磁盘复制/删除速度已加快。

## 提交反馈

- 请求成功返回任务 ID 后，收起右侧大抽屉，保留右下轻量任务提示，可继续操作页面；可点击“查看进度”。提交接口失败时原表单保留错误。
- 状态轮询：前期 1.5 秒，持续任务降为 4 秒；隐藏页面暂停，恢复可见立即查询；无并发轮询、卸载后忽略旧响应。网络失败退避到最多 15 秒，提示不等于任务失败，不自动重提操作。
- 执行成功自动关闭提示并使用原回调刷新相关资源；执行失败/取消自动展开详情并保留错误，用户可手动收起或关闭。
- 页面内提示不是持久任务中心。离开页面/关闭提示后仍可在“任务”中查看任务，不会取消服务端操作。
- 任务中心服务端分页 20 条，状态筛选覆盖全部授权任务；5 秒刷新当前页，页面不可见时暂停。手动打开的历史详情保持可查看，不因成功自动消失。

## 页面整理

- 统一桌面导航 232px、内容间距 24px、窄桌面 16px、48px 表格行高与 8px 圆角；保留现有白色导航设计语言。
- 数据卷合并重复标题和大面积统计卡，改为过滤工具栏、紧凑摘要、数据表及固定操作列。
- 用户创建/编辑/详情改为抽屉，角色用复选框明确多选，配置不再堆在长列表下方。
- 镜像上传及节点登记默认折叠，保持组件挂载，避免折叠即中断上传；镜像列表为主体。
- 统一工具栏换行、详情标签横向滚动与抽屉长文本处理；控制台既有专属布局保留。

## 验证与限制

使用隔离 PostgreSQL 数据库运行后端测试；并行测试用屏障确认两个独立任务重叠执行、各领取一次且未超量领取。前端测试覆盖成功/失败终态、暂停/恢复、退避、无重叠请求及卸载后丢弃响应。

没有为了验证而创建、删除或停止生产虚拟机，也没有执行卸载脚本。没有给出无实测依据的性能百分比；实际收益取决于任务类型、节点 IO 和资源容量。
