# 用户、角色与权限管理

本模块沿用 Django User、Group、Permission 和现有节点 ACL。所有管理 API 都校验平台管理员身份及对应权限；普通用户不能通过自行构造请求进入账号管理。资源操作继续由后端检查操作权限、本人资源所有权、节点 ACL 和节点范围。

## 用户生命周期

- 支持用户名、显示名、邮箱、备注、多个角色、启用状态、节点范围及个人配额。用户名创建后不可修改，大小写冲突拒绝创建；角色必须存在且启用。
- 不提供密码的新账号设置为待激活、禁止登录。管理员单独重置密码取得一次性显示的临时密码，然后启用账号；首次登录必须修改密码。
- 修改角色、节点范围、启用状态及重置密码会递增会话版本，旧登录会话在下次请求时失效。普通 noVNC 会话立即停止授权续租，并由既有清理任务关闭过期连接。
- 禁用或撤销最后一个有效管理员会被拒绝，并使用数据库事务锁防止并发绕过。禁用保留账号、资源归属和审计记录。
- 配额支持实例数、vCPU、内存 MiB、磁盘 GiB。个人填写项覆盖系统默认值，未填写项继承默认值；不会因为拥有多个角色而叠加配额。降额不自动删除已有资源，后续创建按额度检查。

## 批量导入

支持 UTF-8 CSV 和单工作表 XLSX，提供模板下载。每批最多 1,000 行，原文件最多 5 MB；拒绝宏格式、加密文件、公式、非白名单字段、重复表头及超限压缩内容。

| 字段 | 含义及规则 |
| --- | --- |
| username | 必填；文件内按大小写不敏感查重，冲突行全部标记失败 |
| display_name | 新增账号必填，最多 64 字符 |
| email | 可选；更新时空白保持原值，`__CLEAR__` 清空 |
| role_codes | 新增必填；角色编码以分号分隔；更新填写后替换角色集合 |
| status | pending、active、disabled；新增只能待激活；无可用密码不能启用 |
| node_ids | 分号分隔节点 ID；`[]` 禁止所有节点，`__CLEAR__` 恢复继承；空白保持原值 |
| quota_instances | 非负整数；实例数覆盖值 |
| quota_vcpu | 非负整数；vCPU 覆盖值 |
| quota_memory_mib | 非负整数；内存 MiB 覆盖值 |
| quota_disk_gib | 非负整数；磁盘 GiB 覆盖值 |
| remark | 最多 500 字符；空白保持原值，`__CLEAR__` 清空 |

其余更新字段空白表示不修改。清除个人配额覆盖值通过用户编辑完成。用户名、权限标志、密码、哈希、会话凭证不支持作为更新提权字段；密码和权限标志也不接受作为导入列。

导入流程：上传 → 逐行预校验 → 查看新增/更新/错误记录 → 确认 → 后台任务执行 → 下载逐行结果。

- 新增模式拒绝已有账号；更新模式拒绝不存在账号；合并模式按用户名决定新增或更新。
- 严格模式要求全部行通过预校验，执行阶段任一失败整批回滚；部分成功模式独立提交有效行并保留失败原因。
- 确认前后若目标账号或关联角色发生变化，相应记录要求重新预校验，防止覆盖他人的修改。
- 同一批次重复确认返回原任务；每行修改及结果写入同一事务，worker 恢复时跳过已提交记录。失败批次不能通过通用任务重试直接重放，应修正失败记录并新建预校验。
- 结果报告包含原始行号、用户名、状态、错误码及字段错误，不含密码。可只修正失败行再次导入。

## 批量导出

支持 CSV/XLSX、所选账号、当前搜索/角色/状态筛选结果或全部账号，每次最多 10,000 个用户。任务提交时固定用户 ID 集合，后台生成文件时读取字段当前值。

- 可选字段：上述导入字段及 created_at、updated_at、last_login。
- 默认不包含邮箱、备注；这两列额外需要 `accounts.export_sensitive_user`。
- 永不导出密码、密码哈希、令牌、会话或节点凭据；可疑公式文本按字符串转义。
- 导出的时间字段只读，不能直接作为导入列；重新导入前按模板保留可写字段。
- 导入预览、批次结果和导出文件有效期 30 分钟，仅提交者且仍具备相应权限时可读取。过期文件不能下载，清理定时器擦除其原始行、结果及文件内容，保留批次审计元数据；界面支持主动清理已完成批次。

## 角色管理

| 角色 | 适用范围及关系 |
| --- | --- |
| Admin | 平台管理员，管理全局资源与账号；内置规则不可编辑、删除 |
| Operator | 现有操作员/学员角色，允许操作授权节点上的本人资源，无账号及系统管理权 |
| Viewer | 现有普通用户角色，可创建及操作本人虚拟机，并非严格只读角色 |
| 自定义角色 | 从受支持的业务权限选择，可配置本人资源或指定节点上的本人资源范围；可建立严格只读角色 |

- 创建需要唯一且不可变的编码（小写字母开头，3–48 个小写字母、数字或下划线）、显示名称、权限与资源范围；描述可选。
- 权限目录由后端实际 Permission 提供，账号/系统管理、全局网络修改等权限不能通过自定义业务角色分配。操作权限依赖相应查看权限，不完整的组合会被拒绝。
- 编辑采用版本校验，拒绝覆盖并发修改；禁用角色会撤销其实际权限，重新启用恢复配置。有关联用户的角色不可删除，需先解除分配。
- 不设置角色继承。多角色按“同一操作的授权范围”合并，再与用户节点范围及节点 ACL 取交集；不会把某角色在节点 A 的查看权限扩大为另一角色的启动权限。
- 无论自定义角色如何配置，非管理员只能管理本人虚拟机、本人任务。管理员与普通用户的授权边界不会由隐藏按钮决定。

现有项目没有独立项目/租户实体，因此本次实现节点范围及个人配额，不提供虚假的项目隔离。共享网络白名单和规格模板仍按原有全局只读目录处理；跨用户运维角色需要后续引入明确的资源授权模型。

## API 与部署

- 用户：`GET/POST /api/v1/users`，`GET/PATCH/DELETE /api/v1/users/{id}`。
- 角色：`GET/POST /api/v1/console/roles`，`PATCH/DELETE /api/v1/console/roles/{id}`，`GET /api/v1/console/permissions`。
- 模板：`GET /api/v1/users/import-template?file_format=csv|xlsx`（避免与 DRF 的格式协商参数冲突）。
- 批次：`POST /api/v1/users/batches`；导入使用 multipart file、mode、strict；导出使用 JSON kind=export、format、fields、ids 或 filters。
- 批次状态/确认/清理：`GET/POST/DELETE /api/v1/users/batches/{id}`；下载：`GET /api/v1/users/batches/{id}/download`。
- 独立权限：manage_user、manage_role、import_user、export_user、export_sensitive_user。创建、更新、禁用、重置、角色变化、批次和下载均写入审计。
- 更新后安装 Python requirements，执行 migrate、sync_roles，重启 management/worker 并重建前端。安装脚本同时启用 `cloudvirt-cleanup_account_batches.timer`；手工部署需配置定期执行 `manage.py cleanup_account_batches`。

本模块不包含串流或共享工作台功能。
