# 2026-10-30 平台加固记录

基于用户提供的 `192.168.100.100` 扫描报告。本次按要求不修改 SSH root 登录策略或口令。

## 已修复

- 登录失败和锁定后的对外文案统一；未知用户名也在相同的尝试次数后触发 429，避免通过锁定消息枚举账号。
- 登录限流改为 PostgreSQL 中的事务行锁计数，所有 Gunicorn worker 共用。单个来源地址加账号限流，同时限制同一来源地址更换用户名的总尝试次数。计数键为 SHA-256 摘要，过期记录由既有清理任务删除。仅信任本机反向代理传递的 `X-Real-IP`。
- 匿名健康接口只返回 `status`，不再公开应用版本。
- HTTPS 响应增加短期 HSTS、CSP 和 Permissions-Policy；HTTP 80 端口重定向至固定 HTTPS 域名。CSP 只允许本站资源和同源 WebSocket，保留前端现有内联样式兼容性。
- 安装脚本和开发启动脚本同步写入安全头配置；安装脚本移除 nginx 默认站点。
- 实验平台已轮换数据库密码、Django 签名密钥、Agent Token，并依据新签名密钥更新控制台网关密钥；旧网页会话因此失效。轮换后已验证数据库查询、Agent 健康调用与四项服务状态。

## 保留的边界与后续工作

- **root 已失陷时，文件权限、systemd 凭据和密钥搬移都不能阻止 root 读取。** 本次轮换使报告中读取过的旧凭据失效，但在 SSH 入口未处置前，新凭据仍可被再次读取。SSH 入口单独处置后还需再次轮换、撤销旧会话，并检查主机持久化与审计记录。
- 自签名证书仍需由受信任的内网 CA 或正式域名证书替换；短期 HSTS 不替代证书信任。
- CSP 的 `style-src 'unsafe-inline'` 是现有 React 页面内联样式所需，后续可逐步消除内联样式再收紧。
- 控制台网关密钥需要由 nginx 发送到管理服务；当前文件仍仅供 root/nginx 读取。把它改为 systemd `LoadCredential` 不能消除 root 失陷后的读取能力。
