# 实施细化

沿用现有 React、DRF、PostgreSQL、Go Agent 与 libvirt，不升级技术栈。

## 阶段一：可靠创建
1. 后端规范化创建配置，保存不可变快照，旧请求映射默认配置。
2. 将镜像路径/摘要传递 Agent，QCOW2/RAW 独立克隆、ISO 只读挂载。
3. 分离立即启动和宿主机自启，Agent 回读。
4. 修复规格模板私有范围，向导接入模板；新增有版本、发布状态及锁定策略的部署模板。
5. 增加只读 preflight；正式提交重新校验权限/配额/资源并预留。
6. 多盘、多网卡，设备由后端解析授权资源、生成安全路径，全部磁盘进入配额。

## 阶段二：初始化及兼容
1. 节点能力探测与 Agent 功能版本，缓存未知即禁用；旧 Agent 不接收新配置。
2. CPU 模式/拓扑、UEFI/Secure Boot、TPM 分项验证；未验证不能发布对应模板。
3. cloud-init NoCloud 初始化介质，先提供结构化主机名/用户/SSH 公钥。
4. 静态 IP 依赖 IP 池、租约锁、网关/DNS 校验和客体初始化，不能用网卡 XML 代替。
5. 配置来源/版本及用户修改差异展示；初始化与实例运行状态独立。

## 阶段三：性能与设备
1. CPU 配额/绑核、NUMA、hugepages 前置资源探测和权限。
2. 磁盘 I/O 限制/线程和网络带宽，定义统一单位与回读规则。
3. PCI/GPU 发现、IOMMU 分组、设备授权/占用锁、生命周期回收。
4. 黄金镜像制作必须独立任务，检查关机及身份清理，不把配置导出称为磁盘克隆。

## 模块职责
- `apps.instances.configuration`：白名单、规范化、镜像/网络/模板校验；create 与 preflight 复用同一规则。
- `apps.templates`：版本化配置与约束；published 版本不可变。
- `instances.services`：幂等键、事务、配额和资源预留。
- `instances.executors`：使用固定配置快照，将资源 ID 解析为可信 Agent 请求。
- `domainxml`：结构化生成 XML，所有动态值转义。
- `storage`：安全路径、镜像独立复制、原子发布和禁止覆盖。

采用规范化配置快照消除模板更新漂移；部署策略区分镜像/ISO；任务检查点管理可恢复资源生命周期。危险扩展必须通过能力与权限双重校验，不接收原始 XML。

每个阶段先在隔离数据库和测试镜像完成验证，再部署。既有虚拟机、磁盘和配置不做自动变更。
